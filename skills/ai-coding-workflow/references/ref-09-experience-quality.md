# §14 经验质量判定（Experience Quality）

> 适用：向 `memory/patterns.md` 等位置写入经验前的质量判定标准。
> 原则：经验系统的服务对象是 Agent，不是人。判定一条信息是不是经验的标准只有一个——**被召回后，Agent 能否产生正向的行为变更**。
> 本文档供 `SKILL.md A7`、`ref-03 § Phase 10`、`ref-04 § 6.5` 等 `memory/patterns.md` 写入点共用。

---

## 14.1 一句话标准

一条信息值得沉淀，必须同时满足：

1. **能改变 Agent 行为**——召回后让 Agent 更快、更对，而不是「读起来有道理」。
2. **Agent 自己推不出来**——如果 Agent 常规推理就能得出，召回它没有任何额外价值。
3. **来自真实过程且有证据**——不是泛化推断，不是编造。

**反例校准（过程录像 ≠ 经验）**：
- ❌「多试几次就好了」——这是碰运气，不是可复用的判断。
- ❌「遇到复杂问题多收集上下文」——永远对，但没有指导意义，AI 看完不知道下一步干嘛。
- ✅「stop hook 不能同步上报，否则阻塞进程导致超时」——常规推理推不出，且是项目特有的。

---

## 14.2 三镜头：什么值得沉淀（Agent 自推不出的三类）

按「Agent 理解需求的路径」拆成三类认知障碍。命中任一镜头即满足「自推不出」：

| 镜头 | 障碍本质 | 典型场景 | 信息缺口 |
|------|---------|---------|---------|
| **黑话镜头** | 语义不可发现 | 「D 站」字面只是字母 D | 需要显式映射为「盗版站点」 |
| **索引镜头** | 位置不可发现 | 「直达页面功能在哪」 | 需显式指向 `xhome` 模块 `FastCutXXX` |
| **逻辑镜头** | 行为不可发现 | stop hook 同步上报 | AI 常规推理推不出并发阻塞风险 |

> 不用「按主题（前端/后端）或重要性（高/中/低）」分类——那些维度要么无穷无尽，要么依赖主观判断。「Agent 能不能自己发现」是客观可判定的。

**反直觉约束的典型**（逻辑镜头）：
- 「这个目录下的代码访问第三方服务需走特殊代理」
- 「模块间开关引用不能直接用字符串参数，因为开关使用时机问题会导致永远默认关」

这些规则写在 git blame 里但不进文档，换人换 session 必踩——正是最值得沉淀的一类。

## 14.3 九类垃圾特征（写入前先排除）

候选经验命中以下任一条，即为垃圾经验，**不写入**：

| # | 垃圾特征 | 说明 |
|---|---------|------|
| 1 | 事实性错误 | 编造不存在的约束，把临时说法当规则 |
| 2 | 通用常识 | 任何项目都适用，不体现团队特异性 |
| 3 | 对话摘要 | 只复述过程，没有沉淀成可复用判断 |
| 4 | 一次性 case | 只对当前任务有效，不能迁移 |
| 5 | 用户主观偏好 | 个人选择，不代表团队规范 |
| 6 | 缺少上下文 | 不知道对应哪个模块/组件/接口 |
| 7 | 粒度混用 | 一条经验里通用规则与 case 特定信息混杂 |
| 8 | 不可执行 | 只有抽象建议，Agent 看完不知道怎么做 |
| 9 | 证据不足 | 对话里没有足够依据，模型推断过多 |

**方法**：先研究垃圾，再反推好经验——「好经验」难一次定义到位，但「垃圾特征」更容易归纳。

---

## 14.4 写入前检查（三步）

1. **排除九类**（§14.3）：命中任一条即不写入。
2. **源码事实校验（涉及具体 API/类/方法时必做）**：经验中提到的类名、方法名、配置项、路径，先用 `rg`/`grep` 在代码库中检索其存在性再记录。**纯文本自洽不等于真实存在**——曾有经验声称某类应调用 `attachToQBListView()`，源码检索发现该类根本没有此方法，正确方法是另一个类的方法。记录一个不存在的方法，比不记录危害更大。
3. **与历史经验去重/合并**：写入前对比 `memory/patterns.md` 已有条目：
   - 完全重复 → 跳过，不重复写入
   - 同向且有新信息（更具体的场景/触发条件）→ 合并进原有条目，不新增
   - 结论冲突 → 不覆盖旧经验，标注冲突后保留人工裁决（宁严勿宽：误合并造成的边界污染不可逆）

---

## 14.5 默认策略

**宁漏勿错**——把握不足的不写入。误记一条泛泛而谈的经验，比漏记一条具体经验对后续 Agent 的干扰更大。

- **Review 默认保留**：误杀一条高价值经验的代价 > 放行两条边缘经验。
- **去重宁严勿宽**：误合并的边界污染不可逆（When 不同、主结论类型不同、粒度不一致、用途不同都不能合；**禁止桥接合并**——A-B 重叠、B-C 相关，不能推 A-C 重复）。
- **冲突不自动压制**：团队新认知与旧认知不一致本身是有价值的信号，标记后走人工裁决。

---

## 14.6 迭代方法论（作用于记忆/经验规则本身）

「经验质量」从主观感觉变成可讨论、可对齐的对象的路径：

1. 对候选经验做价值标注（高价值/低价值/垃圾）→ 对垃圾做归因 → 归纳垃圾模式 → 转成写入标准。
2. 修改经验规则时用固定流程，不凭感觉：固定对话样本 → 当前规则提取 → 与人工标注对齐 → 分析错例 → 修改规则 → 重新评测 → 对比指标。
3. 三指标一起看：**Recall**（该提取的提了多少）、**Precision**（提取的有多少不是垃圾）、**Garbage Rate**（不该提取的提了多少）。只看 Precision 会过度保守，只看 Recall 垃圾会变多。
